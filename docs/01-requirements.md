# 01 需求：用户、目标、范围与成功标准

## 用户与目标

- **用户**：内容运营人员。
- **目标**：在预算和截止时间内完成一份内容活动方案。
- **价值**：运营人员只需给出主题、预算和截止时间。Agent 负责把“选方案 → 算成本 → 找素材 → 写脚本 → 存方案”走完，并在超预算、工具失败或素材不够时自己调整，而不是中途报错了事。

## 输入与材料

| 输入 | 来源 | 说明 |
|---|---|---|
| 主题、预算、截止时间 | 请求 JSON（`examples/inputs/`）或命令行参数 | 预算单位是“模拟单位”；缺少任一项都不开始执行 |
| 开始时间 | 请求 `start_time` | 模拟时钟的起点，默认当前时间 |
| 工具费用与耗时表 | `data/tools.json` | 每个工具的 `fee`、`fee_on_failure`、`minutes`；脚本生成分三档 |
| 方案模板 | `data/plan_options.json` | P1 旗舰、P2 精简、P3 保底，`priority` 越小效果越好 |
| 合成素材 | `data/materials.json` | 12 条合成素材，不含真实业务信息 |
| 故障注入 | 请求 `simulate.faults` 或 `--fault` | 用于演示和验收，不参与幂等判断 |
| 运行上限 | 请求 `limits` 或 `--max-tool-calls`、`--max-model-turns` | 默认工具调用 15 次、决策 30 次 |

## 工具

| 工具 | 作用 | 费用 | 耗时（分钟） |
|---|---|---|---|
| `estimate_cost` | 成本估算：按费用表算出方案的预计合计费用和完成时间 | 0 | 1 |
| `search_materials` | 素材检索：按主题匹配素材标签 | 2 | 10 |
| `generate_script` | 脚本生成：`premium` / `standard` / `lite` 三档 | 10 / 6 / 3 | 120 / 60 / 20 |
| `save_plan` | 方案保存：唯一的业务写操作，按请求幂等 | 0 | 2 |

工具是本地函数，用合成数据给出确定的结果。试卷允许这样做。

## 交付结果

每次运行都输出：

- **任务计划**：当前计划版本、方案、步骤与依赖（`plan`），以及改选历史（`plan_history`）。
- **步骤状态**：全部步骤的真实状态，包括旧版本计划里失败或被替换的步骤（`steps`）。
- **工具结果**：每次调用的参数、结果、费用、累计费用和模拟时钟（`tool_calls`，每步的完整结果在 `steps[].result`）。
- **费用合计**：账本明细和合计（`cost`）。
- **已保存方案或未完成原因**：`saved_plan` 与 `plan_document`，或 `stop_code`、`incomplete_reason` 与 `gaps`。
- **运行记录**：每一步的决策依据、工具参数、返回摘要和后续动作（`trace`）。

## 范围

**做**：模型逐步决策的循环、成本估算闸门、重试与改选方案、部分成功处理、成功步骤复用、运行状态持久化、重复执行幂等、失败续跑、工具调用与决策次数上限、故障注入、离线 Mock、CLI。

**不做**：界面、线上部署、多 Agent、真实的素材库和脚本服务；并发提交同一请求时的加锁（见 [03 评估](03-evaluation.md)「限制」）；预算或截止时间变更后沿用已有结果（变更后算新请求）。

## 业务约束（来自题目）

1. 模型根据成本超限、工具错误或部分成功结果，调整计划、选替代方案或停止。
2. 保留已成功步骤的结果。
3. 不能把失败步骤记为成功。
4. 没有可行方案时，返回未完成及缺口。

## 成功标准（验收）

| # | 验收点 | 成功标准 |
|---|---|---|
| 1 | 正常完成 | 方案在预算和截止时间内，全部步骤成功，方案已保存，费用合计可以从费用表核算 |
| 2 | 缺预算或截止时间 | 返回 `needs_input` 和缺失字段；不调用工具，不产生费用 |
| 3 | 工具失败 | 可重试且负担得起时可以重试，也可以改选方案；已成功步骤不重跑、不重复计费；失败步骤保持“失败”；没有替代方案时返回未完成 |
| 4 | 预算超限 | 付费步骤执行前发现超限；有可行替代就改选并再估算，没有就返回未完成及缺口。任何时刻累计费用都不超过预算 |
| 5 | 重复执行 | 已完成的请求再次提交时，直接返回已保存的方案；不调用工具、不重复计费、不重复保存 |
| 加分 | 失败步骤续跑 | 未完成的请求再次提交时，保留成功步骤，只补跑失败的部分 |
| — | 部分成功 | 素材不够当前方案时，判断够哪个方案用；部分成功的状态不被改写 |
| — | 运行上限 | 达到工具调用或决策次数上限时，返回 `incomplete` 和明确的 `stop_code`，超限的调用留痕 |
| — | 模型决策 | 每次工具调用都由一次决策选中，模型看到上一步的结果后再选下一步；全部步骤满足后由执行器判定完成；Mock 明确标注只验证流程 |
